# YM-Kithara — M6.10

> **かいさんへ：まずは同梱の「かんたん手順.md」だけ見ればOKです。**
> Visual Studio（「C++によるデスクトップ開発」）を入れて、build.bat をダブルクリックするだけでビルドできます。
> このREADMEは技術メモです。

YMシリーズ第3弾のDAW「YM-Kithara」（M6.8 までは「YM ORPHEUS」）の
マイルストーン **M6.10** です。改名の経緯と互換性については M6.9 セクションを、
今回のスキャン修正については M6.10 セクションを見てください。

M1の範囲は **オーディオトラック＋クリップの配置・非破壊編集＋複数クリップ同時再生＋プロジェクト保存／復元**、
M2 ではそこに **トラックごとのVST3エフェクト（インサート）とプラグイン遅延補償（PDC）** が加わり、
M3 では **MIDIトラック＋ピアノロール＋VST3楽器** と、**WAVミックスダウン書き出し** が加わり、
M3.1 では **MIDIファイル（.mid）の読み込み** が加わり、
M3.2 では **レベルメーター（トラック別ピーク＋マスター）** が加わり、
M3.3 では **エフェクトへのMIDI送信（ライブ入力＋MIDIトラック自身のMIDI）** と
**トラックヘッダ列の固定（横スクロールで流れなくなりました）** が加わり、
M6 では **動画トラック（FFmpegデコード、フレーム同期プレビュー、フィルムストリップ、
カット編集、タイムコード表示）** が加わり、
M6.2 では **mp4書き出し（タイムライン映像＋ミックスダウンを H.264/AAC で）** が
加わり、これで「曲に合わせて映像を切って、1本の mp4 にする」まで通せるようになり、
M6.3 では **動画クリップのクロスフェード（本物のクロスディゾルブ）** と
**SRT読み込み→歌詞テロップ自動生成** が加わりました。あわせて、M6.2 で報告の
あった **mp4読み込み時のフリーズ対策** と、**ドックモニターの廃止**（プレビューは
ポップアウトウィンドウのみに戻りました）を含みます。
M6.4 では **動画クリップの長さもセッションの長さに含める** ようにしました
（Phase 1 の仕様変更）。動画だけのプロジェクトでも再生できるようになり、
音声より長い動画が書き出しで途中で切れることもなくなりました。
M6.5 では **静止画（jpg/png/bmp）を動画トラックに置ける** ようになりました。
タイトルカードやジャケット絵を、動画と同じ感覚で並べて使えます。
M6.6 では **テロップのスタイルをセッション全体で変更できる** ようになりました。
フォント（PCにインストールされたフォントから名前で選択）、表示位置
（下部／中央／上部）、行の揃え（左／中央／右）、文字色、サイズ（40〜250%）を
テキストトラックの「Style...」ダイアログからまとめて設定でき、プレビューと
mp4書き出しの両方に同じ見た目で反映されます。
M6.7 では、その **フォントの「この PC にある／無い」の判定を修正** しました。
M6.6 の判定が厳しすぎて、インストール済みのフォントの一部（しねきゃぷしょん
など）が「無い」扱いになっていた問題への対処です（詳細は M6.7 セクション）。
M6.8 では、長く残っていた宿題の **M4：MIDIキーボード録音** を入れました。
トラックをアーム（●）するとキーボードがそのまま鳴り（止まっていても鳴ります）、
**●Record** か再生で弾いた演奏がテイククリップとしてその場に残ります
（詳細は M4 セクション）。
M6.9 では、製品名を **YM-Kithara** に改名し（ロゴの竪琴はそのまま）、
**MIDIクリップの端ドラッグによるトリム／延長** を他のクリップと揃え、
Windows で文字化けしていた **録音ボタンまわりのラベル** を直しました
（詳細は M6.9 セクション）。
M6.10 では、**プラグインスキャンが大きなコレクションでも完走する** ように
しました（テスター報告：149件／3.25 GB の VST3 フォルダで5分タイムアウトに
なっていた問題）。スキャナが結果を1件ごとに保存する増分方式になり、
本体の打ち切りも「一律5分」から「進捗が120秒止まった時だけ」に変更、
止まっても途中までの結果は取り込まれます（詳細は M6.10 セクション）。
これで「Sunoのステムを編集して、エフェクトを挿して、VST楽器をMIDIで足して、WAVに書き出す」
というDAWのコアが一通り揃います。

想定用途（最終形）：Suno AIで作った曲やステムをタイムラインで編集・エフェクト処理し、
VST楽器をMIDIで足していくWindowsデスクトップDAW。

M0（雛形＋デバイス選択＋単一ファイル再生）は Windows 実機で動作確認済みです。
M1 / M2 は Windows 実機で確認済み（M2 は最終版 M2.1 で「完璧」との評価）。M3 はこれから確認です。

## M1でできること

- **取り込み**：「Import File...」またはウィンドウへのドラッグ＆ドロップ。
  ファイル1つにつき新しいトラックが1本でき、先頭にクリップが置かれます（ステム作業向け）。
  対応形式は WAV / AIFF / FLAC / Ogg / MP3 など JUCE が読めるもの。
  ファイルは一度だけデコードしてメモリに保持し、デバイスのサンプルレートにリサンプルします
  （長いファイルをディスクからストリーミングする方式は後のマイルストーンで）。
- **再生**：全トラックのクリップをサンプル精度でミックスして再生。
  Solo があるときは Solo トラックだけが鳴り、Mute は常に無音。クリップ／トラック／マスターのゲインと、
  クリップのフェードイン／アウト（直線ランプ）が掛かります。
- **編集（非破壊）**：元の音声データは一切変更されません。クリップは「素材への窓」です。
  - クリックで選択、ドラッグで移動（上下にドラッグすると別トラックへ移動）
  - 左右の端（6px）をドラッグでトリム（素材の範囲内まで）
  - 再生ヘッドをクリップ内に入れて「Split at Playhead」で分割
  - Delete キーまたは「Delete Clip」で削除
  - 下部のインスペクターで Fade In / Fade Out（0〜5秒）とクリップ Gain を調整
- **トラック操作**：名前（ダブルクリックで編集）、Mute (M) / Solo (S)、小さい音量スライダー、削除 (x)。
- **ルーラー**：秒表示＋テンポ（BPM）から計算した小節グリッド。ルーラーをクリック／ドラッグでシーク。
  テンポはトランスポート部の数値欄で変更でき、プロジェクトに保存されます。
- **ズーム**：右下の Zoom スライダーで横方向、**V Zoom** スライダーで縦方向（トラックの高さ 40〜160px）を変更。
  タイムライン上で Ctrl＋マウスホイールでも縦ズームできます。
- **プロジェクト保存／復元**：「Save Project...」でフォルダを選ぶと、
  そのフォルダに `project.xml` と `audio/`（素材ファイルのコピー）が書かれます。
  「Open Project...」でフォルダを選ぶと、トラック配置・トリム・フェード・テンポ・各種ゲインまで復元されます。
  素材ファイルが見つからない場合は警告を出し、そのクリップだけを落として読み込みます。

## M2でできること

- **VST3スキャン（初回のみ）**：画面下部の「Scan for Plugins...」を押すと、別プログラム
  **OrpheusVstScanner** が起動して、PC内のVST3プラグイン（標準のインストール先）を調べます。
  スキャンはアプリの外で走るので、壊れたプラグインがいてもDAW本体は落ちません
  （問題のあるファイルは次回スキャンで先に飛ばされる仕組み付き）。
  結果はユーザーのアプリデータフォルダ（`YM ORPHEUS/plugin-list.xml`）に保存され、次回からは不要です。
- **トラックFX**：クリップを選ぶと、そのトラックが下部のFX欄の対象になります。
  「Add FX...」でスキャン済みプラグインの一覧（メーカー順）から選んで追加。
  各スロットに **Open**（プラグインの画面を別ウィンドウで開く）、**Bypass**、**Remove** があります。
  エフェクトは挿した順に処理されます。
  挿したエフェクト名は各トラックヘッダのトラック名の下にも「FX: 名前 > 名前 (off)」の形で表示されます
  （バイパス中は `(off)`、見つからない場合は `(missing)`。トラック高さ 52px 未満では非表示）。
- **PDC（プラグイン遅延補償）**：プラグインが報告する遅延サンプル数をトラックごとに合計し、
  一番遅いトラックに合わせて他のトラックを遅らせることで、トラック同士のタイミングを揃えます。
  エディタを閉じたタイミングでも再計算します。
- **保存／復元**：FXの並び・バイパス状態・プラグイン内部の状態（ステート）が project.xml に保存されます。
  プラグインが見つからない環境で開いた場合は「名前 (missing)」の仮の行として残り、
  名前とステートは保持されたまま再保存できます。M1/M1.2 のプロジェクトもそのまま開けます。
- ※ Windows自体にはVST3プラグインは付属していません。何も入れていないPCでは、
  スキャンが終わっても一覧は空です（それで正常です）。
  Cakewalk Sonar 付属のエフェクトなど、標準フォルダ（`C:\Program Files\Common Files\VST3`）に
  入っているVST3は検出されます。楽器（シンセ）プラグインも一覧に出ますが、
  トラックに音を足す用途は M3（MIDIトラック）で扱います。

## M3でできること

- **MIDIトラック**：上部の「Add MIDI Track」で追加。オーディオクリップは持たず、
  代わりに **楽器スロット（1つ）** と **MIDIクリップ** を持ちます。
  楽器はM2のFXと同じ仕組み（同じインスタンス管理・同じ保留リスト方式）でホストされ、
  楽器の後段には通常のFXチェーンもそのまま挿せます。楽器の遅延もPDCに含まれます。
  楽器が無い／見つからないトラックは無音です（missing の場合は名前と状態を保持）。
  トラックヘッダの要約行は MIDI トラックでは「Inst: 名前 | FX: …」の形になります。
- **MIDIクリップ**：レーンの何もない所を **ダブルクリック** で、その小節の頭に
  1小節長（4拍）のクリップを作成。クリップは選択・横ドラッグ移動・Delete 削除が可能
  （M3 v1では移動のみ。別トラックへの移動は今も無し。**端ドラッグのトリム／延長は
  M6.9 で追加** — M6.9 セクション参照）。位置と長さは **秒** で保持し、
  セッション総尺にも数えます。
- **ピアノロール**：MIDIクリップを **ダブルクリック** で別ウィンドウが開きます。
  - 左端が鍵盤（Cの行に音名表示）、横軸はクリップ内の拍（4拍ごとに小節線）、
    縦軸は音程（12px/半音、スクロール可。初期表示は C3〜C5 付近）
  - 空きマスをクリックで音符を追加（0.25拍スナップ、長さは「最後に使った長さ」、
    初期値 0.5拍、ベロシティは 100 固定）
  - 音符はドラッグで移動（音程＋時間、スナップあり）、右端4pxをドラッグで長さ変更
    （最小 0.1拍）、Delete/Backspace または右クリックで削除
  - 変更は即座にエンジンへ書き戻されます（クリップの音符リスト丸ごと差し替え方式）
  - v1の範囲外：再生ヘッド表示、ベロシティ編集、複数選択
- **ノートの時刻モデル（制限事項）**：クリップの位置は秒、クリップ内の音符は **拍** で
  保持し、再生時にセッションのテンポで秒へ変換します。したがって **音符を入れた後に
  テンポを変えると、クリップ内の音符どうしの間隔が伸び縮みします**（クリップ自体の
  位置と長さ＝秒は変わりません）。**曲のBPMは先に合わせてから音符を入れる** 使い方を
  想定しています。
- **ハングノート対策**：停止・シーク・曲の終わりで「全音オフ（CC123＋CC120）」を
  全楽器に1ブロック送る仕組みがあり、音が鳴りっぱなしになりません。
- **WAV書き出し**：「Export WAV...」で保存先を選ぶと、セッション全体
  （＋終わりに2秒の余韻）をオフラインレンダリングして **16bit PCM WAV**
  （エンジンのサンプルレート）で書き出します。楽器・FX・PDC・マスター音量込みで、
  ライブ再生と **同じレンダリング経路** を通します。書き出し中はプログレス表示が出て、
  音声コールバックは実体に触りません（再生は自動で止まります）。
- **保存／復元**：トラック種別（`kind="audio|midi"`、無い場合は audio として後方互換）、
  楽器スロット、MIDIクリップと音符が project.xml に保存されます。
  M1 / M2 のプロジェクトもそのまま開けます。

## M3.1でできること

- **MIDIファイル読み込み**：「Import File...」またはドラッグ＆ドロップで `.mid` を渡すと、
  ファイル内の **音符のあるトラックごとに MIDIトラックが1本ずつ** できます
  （音符の無いコンダクタートラック等は読み飛ばします）。
  各トラックには先頭から1つのMIDIクリップが付き、音符がそのまま入ります。
  楽器は付かないので、取り込み後に各トラックへ楽器を挿してください。
  トラック名はファイル内のトラック名メタイベントが使われます（無ければファイル名＋番号）。
- **チャンネルはトラック内で統合**：1つの素材トラック内の複数チャンネルは
  1本のノート列にまとめられます（エンジンの再生がチャンネル1固定のため）。
- **テンポ**：ファイル内の **最初のテンポイベント** がセッションのテンポに設定されます。
  曲の途中のテンポ変更には追随しません（v1の制限）。テンポイベントが無いファイルでは
  セッションの現在のBPMがそのまま使われます。
- SMPTE形式のタイムディビジョンを持つファイルは読み込めません（エラー表示になります）。

## M3.2でできること

- **トラック別ピークメーター**：各トラックヘッダの右端に細いステレオメーター
  （縦バー2本）を表示。タップ位置は **フェーダ後（トラックゲイン適用後）＝実際に
  ミックスへ入る音** で、ミュート中のトラックは無音として表示されます。
  MIDIトラックは楽器の出力がそのままメーターに出ます。
- **クリップLED**：ピークがフルスケール（0.999以上）に達するとバーの上の赤LEDが
  点灯したままになります（ラッチ）。LEDをクリックすると消えます。
- **マスターメーター**：上部トランスポート行の Volume の隣に横型ステレオメーター
  （MASTER）。マスターゲイン適用後の最終出力を表示し、こちらにもクリップLED
  （クリックで消灯）があります。
- メーターは表示専用の状態です（プロジェクトには保存されません）。ピーク取得は
  オーディオスレッド側で atomic なスロットへ store-max するだけなので、
  再生処理への影響はありません。

## M3.3でできること

- **エフェクトへMIDIを送る（ライブ入力）**：起動時にPCのMIDI入力デバイスをすべて開き、
  上部トランスポート行に「MIDI IN: 1 device:（名前）」のように表示します
  （デバイスが無い場合は「MIDI IN: none」）。各トラックヘッダの **「M→FX」** ボタンを
  ONにすると、そのトラックのFXチェーンの全スロットへ、キーボード／コントローラーからの
  ライブMIDI（CCなど）がリアルタイムで届きます。MIDI対応エフェクト
  （例：YM Mirage v1.1 の **ピッチ＝CC1／フリーズ＝CC64／バイパス＝CC65**）が
  YM-Kithara の中でもコントローラーから操作できます。
  設定はトラックごとに project.xml へ保存されます（属性 `fxMidiIn`。
  M3.2以前のプロジェクトでは属性が無いため自動的にOFFとして読み込まれます）。
- **MIDIトラック自身のMIDIもFXへ**：MIDIトラックでは、クリップから生成されるMIDIが
  楽器だけでなく **後段のFXチェーンにも** 渡ります（将来のCC編集や、ノート反応型
  エフェクトへの布石）。なお現在のクリップモデルが保持するのはノートのみで、
  `.mid` 内のCCは取り込まれません（M3.1の仕様どおり）。
- **書き出しにライブ入力は入りません**：WAV書き出しはオフライン処理なので、
  ライブMIDIは届きません（仕様）。MIDIトラックのクリップMIDIは書き出しでもFXへ渡ります。
- **トラックヘッダ列の固定**：タイムラインを横スクロールしても、左端のトラック情報列
  （名前・FX要約・M/S・M→FX・音量・メーター）が流れずに残ります。
  スクロールするのはルーラーと波形エリアだけです。縦スクロールはヘッダとレーンが
  常に揃い、V Zoom で高さを変えても追従します。再生ヘッドの追従スクロールと
  「|<」の先頭戻しは従来どおり（レーン側だけがスクロールします）。
- **実装メモ**：ライブ入力は `juce::MidiMessageCollector` に集められ、音声コールバックが
  ブロック単位で吸い上げて、レンダースナップショットの `fxMidiIn` フラグが立った
  トラックのFXへ配ります（同期はコレクタ内部のロックのみ）。MIDIトラック分は、
  クリップ生成MIDIを楽器へ渡す **前に** 複製してFX用に保持するので、楽器が入力
  バッファを消費してもFXへは確実に届きます。UI側は TimelineComponent
  （ルーラー＋レーン、Viewport内）と TrackHeaderComponent（固定ヘッダ列、Viewport外）
  の2コンポーネントに分かれ、ヘッダ列は Viewport の縦スクロール量だけを同期します。

## M6でできること（動画トラック — Phase 1）

Suno の曲に合わせてミュージックビデオを作るための土台です。**動画のデコードには
FFmpeg**（libavformat / libavcodec / libavutil / libswscale）を使います。JUCE 標準の
VideoComponent は Windows では DirectShow 世代でコーデック依存・同期も粗く、
フレーム取得もできないため採用しませんでした。FFmpeg は **GPL ビルド** を使います
（YM-Kithara 自体が GPL のオープンソース公開前提なので整合します。詳細は
[THIRD_PARTY.md](THIRD_PARTY.md) / [LICENSING.md](LICENSING.md)）。

- **動画トラックは1本だけ**：「Add Video...」ボタン（または動画ファイルをタイムラインへ
  ドラッグ＆ドロップ）で .mp4 / .mov / .mkv / .m4v を読み込むと、動画トラックが
  （無ければ）作られ、クリップが末尾へ追加されます。複数読み込むと後ろへつながります。
- **プレビュー**：トランスポート行の **「Video」** ボタンで別ウィンドウのプレビューが
  開きます。再び押す／ウィンドウを閉じると消えます。再生・停止・ルーラーのクリック
  （シーク／スクラブ）に **フレーム単位で追従** し、アスペクト比を保ってレターボックス
  表示します。クリップの無い位置では黒画面になります。
- **フィルムストリップ**：動画レーンには、クリップが使っている元動画の **1秒ごとの
  サムネイル** が並びます（バックグラウンドで抽出するので、表示直後は単色→順次絵に
  置き換わります）。クリップ操作はオーディオと同じです：ドラッグで移動、両端ドラッグで
  トリム（元動画の範囲内まで）、選択して Split ボタン／Delete。
- **クリップの対応付け**：タイムライン位置 t の映像は、クリップの
  「開始位置・元動画オフセット・長さ」で **元動画時刻 = オフセット + (t − 開始位置)**
  に変換され、その時刻のフレームが表示されます。プロジェクトには動画ファイルの
  **絶対パス** で参照が保存されます（動画ファイル自体はプロジェクトフォルダへ
  コピーされません。ファイルを移動すると、そのクリップは読み込み時に警告つきで
  落ちます）。
- **タイムコード表示**：トランスポート行に大きなモノスペース表示
  `HH:MM:SS;FF`（ドロップフレーム時）／ `HH:MM:SS:FF` を追加しました。
  セッションはタイムコードのフレームレート（分子／分母＋「ユーザーが固定したか」の
  フラグ）を保持し、project.xml に保存されます。**最初の動画を読み込んだとき、
  ユーザーが固定していなければ、そのクリップの fps を自動採用** します。
  右隣のプルダウン（23.976 / 24 / 25 / 29.97 DF / 30 / 50 / 59.94 DF / 60）で選ぶと
  その値に固定されます。動画が無く未固定なら 30 fps です。
  - ドロップフレームは 30000/1001（29.97、2フレーム落とし）と
    60000/1001（59.94、4フレーム落とし）のみ。実時間1時間がちょうど
    `01:00:00;00` になるのがドロップフレームの定義です。なお **実時間ちょうど
    60.0 秒は `00:00:59;28`** と表示されます（0分目は「10分目」扱いで何も落とさない
    ため、`00:01:00;02` は実フレーム1800＝約60.06秒のラベルです）。
  - 23.976（24000/1001）は 24 カウントのノンドロップ（':' 区切り）で表示します。
  - タイムライン内部は今まで通り「秒」なので、fps は表示専用の換算です。
- **アプリアイコン**：JUCE デフォルトから、かいさん選定の **金のリラ（竪琴）の
  アイコン** に変わりました（`Resources/orpheus-icon.png` を CMake の
  `ICON_BIG` / `ICON_SMALL` に指定し、Windows では exe／ウィンドウのアイコンとして
  埋め込まれます）。タスクバーやエクスプローラーでリラのアイコンが見えます。

### Phase 1 の制限（仕様）

- **動画ファイル自体の音声は使いません**。音は従来どおりオーディオトラック側で
  用意してください。動画トラックは音声レンダリング・PDCには一切影響しません。
  ただし **セッションの長さには動画クリップの終わりも含まれます**（M6.4 で
  仕様変更。Phase 1〜M6.3 では含みませんでした）。そのため動画だけの
  プロジェクトでも再生でき、WAV／mp4 書き出しの範囲（セッションの長さ＋2秒）
  も動画の最後まで届きます。
- 動画トラックに FX・楽器・メーター・音量はありません（ヘッダは名前と削除ボタンだけ）。
- デコードはプレビュー専用のバックグラウンドスレッド（最新リクエスト優先）で行い、
  オーディオスレッドと画面スレッドはデコードでブロックしません。フィルムストリップも
  専用スレッドで抽出し、キャッシュが上限（900枚）に達したらまとめて空にします
  （LRU ではありません。割り切った簡略化です）。
- **Phase 2（M6.2 で実装済み）**：mp4 書き出し（タイムライン映像＋ミックスダウンを
  H.264/AAC に。9:16 縦動画は書き出しサイズのプリセットとして含む）。残りは
  クロスフェード、SRT 読み込み→歌詞テロップ自動生成（Phase 3 以降）。

## M6.2でできること（mp4書き出し — Phase 2）

- **「Export MP4...」ボタン**（「Export WAV...」の隣）：動画トラックが無い場合は
  その旨を表示して止まります（無言で失敗しません）。動画トラックがある場合は
  まず設定ダイアログが出ます。
  - **サイズ**：Original（先頭クリップの寸法を偶数に丸め）／ 1920×1080 ／
    1280×720 ／ **1080×1920（縦 9:16）**
  - **画質**：High（CRF 18）／ Standard（CRF 23）／ Light（CRF 28）。libx264 の
    プリセットは veryfast 固定です
  - **フレームレート**は常にセッションのタイムコード fps です
    （フレーム数 = 書き出し尺 × fps）
- **書き出し範囲は WAV 書き出しとちょうど同じ**（セッション尺＋2秒の余韻）なので、
  mp4 の音声は WAV ミックスダウンと一致します。クリップの無い時間は黒フレームです。
- **はめ込みルール**：元動画はアスペクト比を保ったまま出力フレームに収め、
  余りは **黒帯** で埋めます（引き伸ばし・切り抜きはしません）。縦動画プリセットに
  横動画を入れると上下に黒帯が付きます。
- **フレームのサンプリング**：出力はタイムコード fps でタイムラインを刻むため、
  元動画の fps が違えばフレームの複製／間引きが起きます（音に同期するのが正で、
  映像は一番近い瞬間の絵が選ばれます）。サイズの違うクリップが混ざっても同じ
  ルールではめ込まれます。
- **パイプライン**：書き出しは専用スレッド＋プログレス表示で走り、映像は
  プレビューとは別の専用デコーダで単調に読み進めます（シークはクリップ境界だけ）。
  音声は既存のオフライン経路（`beginOfflineMixdown` 系）でチャンク描画し、
  libswresample で 48 kHz 化して **AAC 192 kbps** にエンコードします
  （PTS はサンプル単位で正確）。コンテナは **faststart** 付き mp4 です。
- **キャンセル**：プログレス表示のキャンセルで書き出しを中断できます。その場合、
  書きかけのファイルは **削除** されます（中途半端な mp4 は残りません）。
- **素材チェック**：開始前に全クリップの元ファイルを検査し、見つからないものが
  あれば **ファイル名を出して** 中止します。

  - 抽出はバックグラウンドで進み、プログレス表示からキャンセルできます。

## M6.3でできること（クロスフェード＋SRTテロップ — Phase 3）

### 動画クリップのフェードとクロスディゾルブ

- **クリップごとのフェードイン／フェードアウト**（秒、既定 0、プロジェクトに
  保存されます）。付け方は、動画クリップの **左上の角を右へドラッグ**（フェード
  イン）／**右上の角を左へドラッグ**（フェードアウト）。フェード範囲はクリップ
  左上・右上の **三角の陰影＋対角線** で描かれます。範囲は 0〜クリップ長で、
  トリム／移動しても長さに合わせて自動で締められます。分割すると左片は
  フェードインを、右片はフェードアウトを引き継ぎ、新しい切り口は 0 です。
- **動画クリップ同士は重ねられます**（動画トラックだけの特例。他のトラックは
  従来どおり重なりません）。タイムライン時刻 t の絵は **共有のレイヤー計算**
  （`VideoComposite.cpp` の `computeLayers`）で決まります：
  - t を覆うクリップを **開始時刻順** に並べ、**最後に始まるクリップが一番上**。
  - 重なり区間 `[上の開始, 下の終了)` では、上のクリップの不透明度が
    **重なり長に対する t の進み具合** で 0→1 に進み、下から上へディゾルブします。
  - 各クリップ自身のフェードイン／アウトは、そのクリップの不透明度にさらに
    掛かります（下に何も無ければ黒からのフェードイン／黒へのフェードアウトに
    なります）。
  - 3本以上の重なりにも同じ規則がそのまま適用されます（書き出し側）。
    プレビューは **上位2レイヤーまで** で合成します（書き出しは全レイヤー）。
- **合成は1実装だけ**：プレビューのフレーム供給（VideoFrameFeed）と mp4
  書き出しが同じ `computeLayers`／`composeFrame` を使います。書き出しでは
  レイヤーごとに独立したデコーダを持ち、各レイヤーを出力サイズに
  はめ込んでから BGR のまま重ね、最後に1回だけ YUV へ変換します。
  レイヤーが1枚だけで不透明度 1、テロップも無いフレームは **M6.2 と
  ビット同一の高速経路** のままです（Phase 2 の書き出し数値は不変）。

### SRT読み込み → テロップ（テキストトラック）

- ヘッダーの **「Import SRT...」** ボタン（または .srt ファイルの
  ドラッグ＆ドロップ）で、字幕ファイルから **テキストトラック**（最大1本、
  無ければ自動作成）に **テロップクリップ** が並びます。既にクリップがある
  場合は **末尾に追加** されます（重なりは描画時に **後から始まる方が勝ち**）。
- **パーサの許容範囲**（`SrtParser.cpp`）：UTF-8 BOM、`\r\n`、番号行の欠落を
  許容。時刻は `H:MM:SS,mmm`（`.` 区切り・ミリ秒の桁不足も可、位置メタデータは
  無視）。`<...>` タグと `{\...}` 上書きブロックは取り除かれます。
  **壊れたエントリ**（時刻行が読めない／終了≦開始／テキストが空）は
  スキップされ、読み込み結果は **「N 本追加、M 本スキップ」を必ず表示** します。
- **テロップの描画**（共有ヘルパ `Telop::drawOnto`）：画面下部中央、**白の太字
  サンセリフ（高さ ≒ 画面高の 5.5%）＋黒の縁取り**。行の折り返しはしません
  （SRT の行がそのまま行になります）。**映像の無い区間でも**、黒画面の上に
  テロップだけは表示されます（歌詞だけの間奏など）。デコーダのキャッシュ
  フレームには決して描かず、公開用コピー／書き出しキャンバスにだけ合成します。
- **編集**：テロップクリップは移動・トリム・分割・削除が他のクリップと同様に
  でき、**ダブルクリックでテキスト編集ダイアログ**（複数行）が開きます。
  レーンには1行目が表示されます。
- **文字サイズ**：テキストトラックのヘッダーにある **Telop S / M / L** が
  セッション全体の倍率です（0.72 / 1.0 / 1.38 倍、プロジェクトに保存）。
  それ以外のスタイル（色・フォント・位置）は M6.3 では固定でした
  （**M6.6 で変更可能になりました**：下記の M6.6 セクション参照）。

### ドックモニターの廃止（かいさんの判断）

M6.2 で追加したメイン画面内の小型モニターは **廃止** しました。プレビューは
**VIDEO ボタンのポップアウトウィンドウだけ** に戻っています。副次効果として、
フレーム供給（VideoFrameFeed）は **ウィンドウを開いている間だけ** 動き、
**動画を読み込んだだけではデコードが一切始まらなく** なりました
（Phase 1 と同じ挙動。下記のフリーズ対策と直結します）。

### mp4読み込みフリーズの調査と対策

M6.2 での報告（「mp4を読み込むとフリーズする。2分待っても復帰しない。
複数の普通の mp4 で全部同じ」）を受けて、読み込み→初回フレームの経路を
精査しました。Linux 上の再現テスト（実際の MainComponent を使い、読み込み→
供給→シーク→破棄をウォッチドッグ付きで繰り返すハーネス）では **フリーズは
再現しませんでした**（読み込み 1〜11 ms、初回フレーム約 120 ms、メッセージ
処理の最大スライス約 41 ms、126項目すべて通過）。このため **監査で見つけた
ハザードを潰す** 形の対策になっています：

1. **デコード開始の契機（Phase 2 の回帰ベクトル）**：ドックモニターが常時
   リスナーだったため、M6.2 では **読み込み直後から** デコードが走っていました
   （Phase 1 はウィンドウを開くまで何も始まらない）。モニター廃止により
   Phase 1 の挙動に戻りました。
2. **フレーム配信コールバックの競合**：デコーダ側のコールバック
   （`std::function`）を、メッセージスレッドが書き、ワーカースレッドが
   無同期で読んでいました。ロック付きのセッタ（`setOnFrame`）に変更し、
   配信はロック下でコピーしてから呼ぶ形にしました（フィルムストリップ側も同様）。
3. **フィルムストリップの集中アクセス**：読み込み直後の描画でクリップ全秒分の
   サムネイルが一斉にキューされ、到着のたびにタイムライン全体が再描画されて
   いました。→ **画面に見えている範囲だけ** をキューし、再描画はタイマーで
   **まとめて1回** にし、キューにも上限（240件）を設けました。
4. **デコードの無制限ループ**：`getFrameAt` にフレーム数／パケット数の上限が
   無く、病的なストリームでワーカースレッドが永遠に回る可能性がありました。
   → 上限（フレーム 8192／パケット 65536）を設け、到達したら最良のフレームを
   返して打ち切るようにしました。

Windows 実機での最終確認はチェックリスト（M6.3）にあります。

## M6.4の変更（動画もセッションの長さに含める）

M6.3 の実機確認で「動画だけ読み込んでも Play が押せない」という報告がありました
（読み込み自体は正常で、フィルムストリップも表示される）。原因は Phase 1 の
仕様で、セッションの長さが音声／MIDIクリップからしか決まらず、動画だけの
セッションでは長さが 0 になっていたことです。M6.4 で仕様を変更しました：

- セッションの長さ＝ **オーディオ／MIDI／動画クリップの終わりの最大値**
  （`TimelineEngine::computeTotalLengthLocked` の1か所で計算し、トランスポートの
  停止位置・再生ヘッドのクランプ・Play の有効化・両書き出しの範囲はすべて
  ここから決まります）
- **動画だけでも再生できます**：Play が有効になり、再生ヘッドは動画の最後まで
  進んで止まります。シーク／スクラブも動画の範囲いっぱいまで届きます
- **音声より長い動画** は、再生・プレビュー・書き出しのどれでも途中で
  切れなくなりました。WAV／mp4 書き出しの範囲（セッションの長さ＋2秒の余韻）も
  動画の最後まで伸びます
- 動画トラックが **音声レンダリングや PDC に影響しない** 点は従来どおりです
  （変わるのは「長さ」だけ）。音声だけのプロジェクトの長さはミリ秒単位で
  従来と同一です。プロジェクト形式（XML）にも変更はありません

Windows 実機での確認はチェックリスト（M6.4）にあります。

## M6.5の変更（静止画を動画トラックに）

かいさんの要望（「静止画（jpgやpng）も乗るかな？」）への対応です。FFmpeg は
画像ファイルを「1フレームだけの動画ストリーム」として読めるので、動画と
まったく同じ経路で取り込みます：

- **対応形式：jpg / jpeg / png / bmp**。「Add Video...」の選択フィルタと、
  ウィンドウへのドラッグ＆ドロップの両方から読み込めます
- **静止画の判定** はプローブ時に行います（画像コーデック MJPEG/PNG/BMP が
  画像デマルチプレクサ（image2 / *_pipe）の後ろにある、またはストリーム全体が
  1フレーム分しかない）。判定は `VideoFileInfo::stillImage` → クリップの
  `stillImage` フラグに乗り、プロジェクトには `still` 属性として保存されます
  （無いファイル＝従来どおり動画クリップとして扱われます）
- **置いた直後は 5 秒** のクリップになります。絵が変わらないので **長さは
  自由** です：右端はソースの長さに縛られず何秒にも伸ばせ、左端は開始位置の
  移動だけ、オフセットは常に 0。分割すると両方とも静止画クリップになります
- デコーダ側で「静止画は **どの時刻にも同じ1フレームを返す**」を保証します
  （1回だけデコードしてキャッシュ。画像ストリームへのシークや EOF は扱い
  ません）。プレビュー側も静止画レイヤーには **固定のリクエストキー** を使う
  ので、再生ヘッドが動いても再要求は走りません
- そのまま効くもの：プレビュー表示、フィルムストリップ（同じ絵が並びます）、
  セッションの長さへの算入（M6.4 の規則どおり）、**クロスフェード**
  （静止画→動画・静止画同士のディゾルブ）、黒フェード、**テロップの合成**、
  **mp4 書き出し**（全サイズプリセット）
- 静止画に音声は無いので、**Extract Audio は静止画クリップを黙って
  スキップ** します（「音声なしファイル」として報告もしません）
- 静止画の名目フレームレート（画像デマルチプレクサの 25 fps）は
  セッションのタイムコードレートには **採用しません**（絵にフレーム
  レートは無いため）

Windows 実機での確認はチェックリスト（M6.5）にあります。

## M6.6の変更（テロップのスタイル）

かいさんの要望（「フォントはPCにインストールされてるものを使えたらベスト。
500以上入ってるので全部読み込むのは重そう。何かいい案ない？」＋位置／揃え／
色／サイズの変更）への対応です。答えは **「名前だけ列挙して、実体化するのは
選んだフォントだけ」** です：

- **入り口**：テキストトラックのヘッダーに **「Style...」ボタン** が増えました。
  ダイアログ1つで **フォント／サイズ／位置／揃え／色** をまとめて編集できます。
  変更は **その場でセッションに反映** されるので、後ろのプレビュー画面が
  リアルタイムに追随します。**Cancel（またはウィンドウを閉じる）で開く前の
  状態に戻り**、OK で確定します。ダイアログ下部にはサンプルテロップの
  **ライブプレビュー帯**（描画は書き出しと同一の `Telop::drawOnto`）があります
- **スタイルの中身**（セッション全体に1つ、プロジェクトに保存）：
  - **フォント**：名前で指定（空＝既定のサンセリフ太字）
  - **サイズ**：40〜250% のスライダー。ヘッダーの **Telop S/M/L と連動**
    （S/M/L は 72/100/138% のプリセットとして同じ値を読み書きします）
  - **位置**：下部（M6.3 と同じ）／中央／上部
  - **揃え**：左／中央／右（行ごとの justify。左・右は画面幅の 4% の余白付き）
  - **色**：プリセット7色（白・黄・シアン・緑・赤・マゼンタ・黒）＋
    **Custom...**（カラーセレクタ）。**縁取りは自動**：文字色の輝度で判定し、
    明るい文字には黒縁、暗い文字（紺など）には白縁が付きます
  - 既定値（フォントなし・100%・下部・中央・白）は **M6.3 の見た目と完全一致**
    です。行の自動折り返しは従来どおりしません
- **フォント選択の仕組み（重くしない工夫）**：
  - 一覧は **名前だけ** を列挙します（`juce::Font::findAllTypefaceNames()`）。
    列挙は **アプリ起動後の初回だけ・バックグラウンドスレッド** で行い、
    結果はアプリ実行中キャッシュされます（この Linux 環境では 212 件を
    約 1.5 ms で列挙。Windows の 500 件超でも名前だけなので軽いはずです）
  - **フォント実体（タイプフェイス）を生成するのは、選択中／プレビュー中の
    1 件だけ** です。ピッカーのリスト行も既定フォントで描きます
    （全フォントで1行ずつ描くようなことはしません）。ピッカーには
    **検索欄** と、選択中フォントでの **サンプル表示**
    （`Aa Bb 123 あ ア 亜 歌`：ラテン・数字・かな・漢字の収録具合が
    一目で分かります）があります
  - 解決したタイプフェイスは **名前キーでキャッシュ** され、書き出しの
    数百フレームでも再生成されません。**この PC に無いフォント名** は
    既定サンセリフに **フォールバック** して描かれ、ピッカーとダイアログでは
    「この PC には無い」旨が表示されます（別 PC で作ったプロジェクトを
    開いても壊れません。見た目だけ着替えます）
- **保存形式**：プロジェクト XML のルート属性 `telopFont` / `telopScale` /
  `telopVPos` / `telopAlign` / `telopColour`（16進 ARGB）。従来の
  `telopSize` も引き続き書き出します。読み込みは、**`telopScale` があれば
  それを正** とし、無い旧ファイルは `telopSize`（S/M/L）→ 72/100/138% に
  変換します。テロップ属性が一切無いファイルは完全な既定値になります

Windows 実機での確認はチェックリスト（M6.6）にあります。

## M6.7の変更（フォント判定の修正＋サブタイトル）

かいさんの Windows 確認で見つかった M6.6 の問題への修正です。インストール
済みのフォントの一部（例：**しねきゃぷしょん**）が、ピッカーで「この PC に
無い」扱いになり、既定サンセリフに落ちていました。

- **何が悪かったか**：M6.6 の「ある／無い」判定は、生成したタイプフェイスの
  ファミリ名が **要求した名前と完全一致** した場合だけ「ある」としていました。
  ファミリ名を複数ロケールで持つフォント（英語名／日本語名）や、列挙された
  名前と生成後の申告名が食い違うフォントは、DirectWrite が正しいフォントを
  生成していても不一致で弾かれていたのです
- **新しい判定**（`Telop::typefaceNameResolved`、純粋関数として切り出し）：
  まず「存在しない名前」を要求して、システムが **代わりに返すフォールバック
  のファミリ名**（無言の置き換えの基準）を一度だけ記録します。その上で、
  次のどれかなら「ある」です：(a) 生成名が要求名と一致、(b) 要求名が
  フォールバックのファミリそのもの（既定フォント自体を選んだ場合）、
  (c) 生成名がフォールバックと **異なる**（＝要求は実在の別フォントに
  ロケール違いの名前で一致した）。「無い」のは、要求が別のものなのに生成物が
  フォールバックそのものだった場合だけです。安全側の性質（置き換えを成功と
  誤認しない）は保たれています。判定は名前キーでキャッシュされ（否定結果も
  含む）、ピッカー／ダイアログの「無い」表示もプレビューも同じ判定と
  生成タイプフェイスを使います
- **サブタイトル**：かいさんの命名で、ヘッダーの「YM ORPHEUS」の直下に
  **「AV Workstation」** のサブタイトル（字間広めの小キャップス、淡色）が
  付きました。ウィンドウ／タスクバーのタイトルも
  **「YM ORPHEUS – AV Workstation」** になりました
- ロケール違いの名前のケース (c) は、この Linux 環境のフォントでは再現
  できないため、スモークでは判定マトリクスを純粋関数の単体テストで
  固定しています。実地の最終判定は かいさん の しねきゃぷしょん です
  （チェックリスト M6.7 の先頭）

## M4でできること（MIDIキーボード録音 — 本体タグ M6.8）

MIDIキーボード（などのMIDI入力）を弾いて、そのままMIDIクリップとして
録音できるようになりました。入口は M3.3 と同じ `MidiMessageCollector`
（起動時に開いた全MIDI入力デバイス）で、テスト用の注入API
`injectMidiMessage` も同じ経路を通ります。

- **アーム**：各MIDIトラックのヘッダーに **●ボタン** が付きました
  （M/S の右、M→FX の左）。複数トラック同時アーム可。アーム状態は
  **ランタイムのみ**で、project.xml には保存されません（開き直した
  プロジェクトがアーム済みで戻ってくることはありません）
- **モニタリング**：アームしたトラックは、ライブ入力がそのトラックの
  楽器にそのまま届きます。**再生中だけでなく、トランスポート停止中も
  鳴ります**（止まった状態でキーボードを弾いて音色を試せます）。
  停止中は専用のモニター専用レンダーパス（アーム済みMIDIトラックだけを
  ライブ入力で鳴らす）が毎ブロック走り、マスターゲインとマスター
  メーターも再生中と同じに掛かります
- **M→FXとの関係**：楽器に届く前に FX 用のコピーを取る従来の順序は
  そのままで、エフェクトがライブMIDIを受けるのは従来どおり
  **fxMidiIn（M→FX）のトラックだけ**です。アームのモニタリングが
  M3.3 のルーティングを変えることはありません（消費者はそれぞれ
  自分のコピーを持つ、M3.3 の教訓どおりです）
- **録音**：トランスポートに **録音ボタン** が付きました（M6.8 では ● 表示、
  M6.9 からは文字化け対策で **「REC」** 表示）。押すと
  現在位置から再生が始まり、アーム済みトラックに録音されます。
  **Playを押した場合も、アーム済みトラックがあれば録音されます**
  （一般的なDAWの標準動作）。録音中はRecordボタンが赤く点きます。
  何も置かれていない空のプロジェクトでも、アームさえあれば
  再生／録音が走ります（テイク自体がセッションの長さを作ります。
  録音開始位置より先に何も無い場合は、セッション終端で止まらず
  開いたまま録音を続けます）
- **タイミング**：ノートの時刻は、コレクタが付けたタイムスタンプ＝
  音声ブロック内のサンプルオフセットから決まります（メッセージ
  スレッドのポーリング時刻ではありません）。音声コールバックが
  **ロックフリーキュー（AbstractFifo、4096イベント）** に絶対位置
  付きで積み、モデル側が 50ms のタイマーポンプで取り込むので、
  音声スレッドがモデルロックを取ることはありません。ヘッドレス
  スモーク（120 BPM）では、t=1.0s に注入したノートが **2.0027拍**
  （目標 2.0 ±0.02）に着地しています
- **テイククリップの作られ方**：アーム済みトラックごとに1つ。
  クリップは **最初のノートが来た時点で、録音開始位置に** 作られ、
  録音しながら再生ヘッドまで伸びていきます。Stop で確定します：
  押さえっぱなしのノートは **停止位置で閉じ**、クリップの終わりは
  max（停止位置、最後のノートの終わり）。**1音も弾かなかったテイクは
  クリップを残しません**。既存クリップとの重なりは可（v1 では
  マージしません）。録音中にアームを外すと、そのトラックのテイクは
  その場で確定します（押さえているノートは現在位置で閉じます）
- **ノートの表し方**：ピアノロールとまったく同じです。秒→拍の変換は
  **セッションのテンポ** で行い、クリップ開始位置からの相対拍で
  保存します。したがって **録音前に曲の BPM を合わせておく** 必要が
  あります（ピアノロールで音を置くときと同じ約束）。録音した
  クリップはそのままピアノロールで編集できます
- **スタックノート対策**：Stop／シーク／アーム解除で、従来の
  オールノーツオフ（パニック）が楽器に届きます。パニックの消費が
  「停止中のみ」から「再生中でも次ブロックで」に変わったので、
  ライブで弾いた音も再生中のシークも取りこぼしません
- **録音されるのはノートON/OFFだけ** です。CC は v1 では録音され
  ません（クリップのモデルがノートだけのため）。CC は従来どおり
  ライブで FX に届きます（M→FX）

  含めず、書き戻し時にそのまま復元するので、**トリムしたクリップを

エンジンとUIを分離するのが設計の決め事です。エンジン側は画面のことを一切知りません。
オーディオスレッドは「レンダースナップショット」（不変の複製）だけを読み、ロックもメモリ確保も
行いません（M1.1で導入）。M2ではスナップショットに各トラックのFXチェーン（解決済みの
プラグインポインタ）とPDC遅延量も載せ、描画はトラック単位
（クリップ→スクラッチバッファ→FX→PDC遅延→加算）になりました。
プラグイン実体はエンジンが保持し、削除された実体は一定時間「保留リスト」で生かしてから
破棄するので、再生中のスナップショットが解放済みメモリを指すことはありません。
M3ではスナップショットにMIDIトラックの楽器ポインタと「拍→秒に変換済みの音符イベント列」
（開始秒でソート済み）も載せ、音声スレッドはブロックごとにノートオン／オフを組み立てて
楽器へ渡します。WAV書き出しも同じ `renderBlock()` を明示的な再生位置で回すだけなので、
ライブ再生と書き出しで音が食い違うことはありません。
M3.3では `renderBlock()` がライブMIDIバッファも受け取るようになり、`fxMidiIn` な
トラックのFXスロットへブロック／チャンク単位で配布します。UI側は M3.3 で
TimelineComponent（ルーラー＋レーン）と TrackHeaderComponent（固定ヘッダ列）の
2コンポーネントに分かれ、ヘッダ列は Viewport の外に置かれて縦スクロール量だけを
同期します（横スクロールでヘッダが消える問題への対応）。

## Windowsでのビルド手順

同梱の **build.bat** をダブルクリックするのが一番簡単です（Visual Studio 2022 / 2026 両対応）。
M6 からは、初回ビルド時に **FFmpeg（約90 MB、BtbN FFmpeg-Builds の GPL 共有ビルド）を
自動でダウンロード** して `deps\ffmpeg` に展開し、ビルド後に DLL を exe の隣へコピーします
（2回目以降はダウンロードしません。`deps\` フォルダは配布 zip には含まれません）。
手動の場合は FFmpeg の SDK 一式（include / lib / bin）を用意して
`-DFFMPEG_ROOT=<そのフォルダ>` を付けてください。Developer Command Prompt で：

```bat
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

実行ファイルは `build\YMKithara_artefacts\Release\YM-Kithara.exe` に出来ます。
M2からは、プラグイン走査用の **OrpheusVstScanner.exe** も同じフォルダに自動でコピーされます
（アプリはまず同じフォルダ、次に `build\OrpheusVstScanner_artefacts\Release\` を探します）。

### ASIOを使う場合（任意）

Steinbergのサイトから ASIO SDK をダウンロードして解凍し、環境変数 `ASIO_SDK_DIR` にそのフォルダを設定してから

## M6.10の変更（プラグインスキャンの完走対応）

テスター環境（VST3 が149件・3.25 GB）で「Scan for Plugins...」が
「The plugin scan took too long and was stopped.」で打ち切られ、大きな
コレクションではスキャンが永遠に終わらない問題への対処です。原因は3つ
重なっていました：①本体がスキャン開始時に結果ファイル（scan-results.xml）を
消していた（スキャナの「前回の結果を読んで続きから」設計が無効化されていた）、
②スキャナは結果を最後に1回だけ書いていた（殺されると全損）、
③本体が進捗と無関係に一律5分でスキャナを強制終了していた。

- **スキャナ（KitharaVstScanner）**：結果 XML を **プラグイン1件ごとに
  書き直す** 増分保存に変更。クラッシュ／強制終了でも失われるのは処理中の
  1件だけで、結果ファイルは常に「そこまでの完全な状態」で残ります。
  起動時に既存の結果を読み、変更のないプラグインはスキップする従来の
  レジューム動作はそのままです
- **本体（YM-Kithara）**：スキャン開始時に結果ファイルを **消さない**
  （レジュームが効くようになりました）。打ち切りは **進捗ベースの
  ウォッチドッグ** に置き換え：結果ファイルの更新時刻＝進捗として、
  **120秒進捗が止まった時だけ** 止めます（全体の上限として60分の
  バックストップあり）。判定は `ScanWatchdog::shouldKill`
  （Source/Engine/ScanWatchdog.h）に分離してスモークでも検証しています
- **進捗表示**：スキャン中のウィンドウに、**いま調べているプラグインの
  ファイル名**（デッドマンズペダル `vst-scan-pedal.txt` の記録）が出ます
- **止まった時の処理**：強制終了しても **途中までの結果を取り込んで**
  一覧を更新し、ダイアログで「いま何件入っているか」「固まったプラグインは
  次回スキャンで末尾に回され（ブラックリスト扱い）」「もう一度スキャンすれば
  **続きから再開** する（最初からではない）」ことを正直に伝えます

### スキャナを手動で走らせる方法（フォールバック）

アプリからのスキャンがどうしても完走しない環境では、スキャナ単体を
コンソールから実行できます：

1. YM-Kithara を終了する
2. コマンドプロンプト／ターミナルで、exe のあるフォルダから実行する：
   `KitharaVstScanner.exe "<アプリデータ>\YM ORPHEUS\plugin-list.xml"`
   （`<アプリデータ>` は通常 `%APPDATA%`。引数のパスに直接書くのが
   ポイントです。この場合、結果は plugin-list.xml 自体に書かれるので
   アプリ側の読込でそのまま使われます）
3. コンソールに `Done: N plugin(s) found.` と出るまで待つ
4. YM-Kithara を起動し直す（一覧が読み込まれています）

## M1.1 修正（音がブツブツ切れる問題）

M1 では、再生中に画面の描画や編集操作と音声処理が同じロックを取り合い、
ロックが取れなかった音声ブロック（10 ミリ秒単位）が丸ごと無音になっていました。
曲を再生しながら画面が再描画されるたびに競合が起きるため、音がブツブツ
切れて聞こえていました。

M1.1 では、音声スレッドがモデルを直接触るのをやめ、編集のたびに作られる
「レンダースナップショット」（不変の複製）を原子的に差し替えて読む方式に
変更しました。音声スレッドはロックもメモリ確保も行いません。編集機能や
プロジェクトファイルの形式は M1 から変わっていません（M1 で保存した
プロジェクトはそのまま開けます）。

お手数ですが、build.bat で再ビルドしてお試しください（手順は今まで通りです）。

## M1.2 改善（再生の追従と Space キー）

M1.1 へのフィードバックを受けて、操作まわりを 2 点改善しました。

- **再生ヘッドのオートスクロール**：再生中、再生ヘッドが画面の右端に
  達すると、表示がページ単位でスクロールして再生ヘッドを追いかける
  ようになりました（一般的な DAW の「フォロー」動作）。止まっている
  ときに手でスクロールした場合は邪魔しません。クリップをドラッグ
  している間も追従を止めます。
- **Space キーで再生／一時停止**：Space を押すと Play / Pause が
  切り替わるようになりました。テンポ欄やトラック名などの文字入力中は
  Space を横取りしません（入力が優先されます）。Audio Settings などの
  ダイアログが開いている間も、Space はダイアログ側のものです。

編集機能やプロジェクトファイルの形式は M1 / M1.1 から変わっていません。
build.bat で再ビルドしてお試しください（手順は今まで通りです）。

## M2 追加（VST3エフェクト＋PDC＋縦ズーム）

M2 では3つ入りました。

- **VST3エフェクト**：走査は別プログラム KitharaVstScanner（M6.9で改名）が担当し、
  DAW本体の中ではプラグインを読みません。トラックごとに挿した順に処理され、
  状態はプロジェクトに保存されます。無い環境では「(missing)」の仮行で残ります。
- **PDC**：プラグイン遅延をトラック単位で合計し、一番遅いトラックに合わせて
  ディレイで揃えます。全トラック遅延0ならディレイ自体をバイパスします。
- **縦ズーム**：V Zoom スライダー（またはタイムライン上の Ctrl＋ホイール）で
  トラックの高さを 40〜160px に変えられます。プロジェクトには保存しません。

プラグインの実体はエンジンが保持し、削除時は「保留リスト」で少なくとも3秒
生かしてから破棄します（再生中のスナップショット対策）。詳しくは
Source/Engine/TimelineEngine.h のコメント参照。

build.bat で再ビルドしてお試しください（手順は今まで通りです）。

### M2 修正（プラグインが一切読み込めない不具合）

最初に出荷した M2 ビルドには、プラグイン情報の保存時に
`PluginDescription::uniqueId / deprecatedUid` を落としてしまう不具合があり、
VST3 のクラス照合が全て失敗して **全プラグインが読み込めませんでした**
（"Could not load the plugin ..."）。この版では `FxSlotData` とプロジェクト
XML に両 ID を保持するよう直し、ID が 0 のまま保存された旧プロジェクトに
ついても、既知プラグイン一覧から名前＋ファイルで引き直して復旧する経路を
`PluginManager::createInstance` に追加しました。読み込み失敗時は JUCE の
エラー文字列もダイアログに表示します。再ビルドしてお試しください。
