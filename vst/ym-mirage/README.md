# YM Mirage — グラニュラー・クラウド VST3（v1.1.0）

入力を細かい「粒（グレイン）」に刻み、ピッチを変えながら時間的に
ぼかして再放出する、霧のような残響感を作る VST3 エフェクトプラグインです。
音声を 4 秒の循環バッファーに書き込み続け、そこから短い粒を
ランダムに拾って雲状に重ねます。**FREEZE** を入れると書き込みが止まり、
つかまえた一瞬の音が無限に持続するパッドになります
（Suno のボーカルやステムをパッド化する用途を想定）。
自作コードのみで実装しています。

Cakewalk Sonar、YM ORPHEUS など、一般の VST3 ホストで使えます。

## 仕組み（正直な注記つき）

| 段 | 内容 |
|---|---|
| 循環バッファー | 入力ステレオを 4 秒のリングバッファーに常時書き込み（FREEZE 中は停止） |
| グレイン生成 | スケジューラーが DENSITY から決まる頻度（約 2–80 粒/秒、指数マッピング）で粒を発火。粒プールは最大 96 個を事前確保し、処理中のメモリ確保・ロックはなし |
| 粒の読み方 | 粒はバッファーの **Mid 信号（(L+R)/2）** を読みます。つまり Wet 経路はいったんモノラル化され、粒ごとにランダムな等パワー・パンで左右に撒き直されます（クラウド系の定番の作り）。**Dry 経路はステレオのまま**です |
| ピッチ | 粒の再生レート = 2^(PITCH/12)。粒ごとに SPREAD 量に応じたランダム・デチューン（最大 ±1% × SPREAD）が付きます |
| 窓 | 各粒に Hann 窓（sin²）を通すので、粒の継ぎ目でクリックは出ません |
| 位置の安全策 | 粒の開始位置（アンカー）は「書き込みヘッド −（粒の長さ × レート）− 安全マージン 2 ms」より手前に置かれ、速い粒が書き込みヘッドを追い越すことはありません。SMEAR はここに最大 +2 秒のランダムな履歴オフセットを足します（バッファー範囲内にクランプ） |
| レベル補正 | 粒はランダム位相で重なるため、期待重なり数 N に対して 1/√N の正規化を Wet にかけています（DENSITY / SIZE を上げても音量が暴れません） |
| FREEZE | 書き込みヘッドが止まり、バッファーの中身が保存されます。粒は凍った素材から発火し続けるので、雲は無限に持続します。Dry は MIX の設定どおり流れ続けます。窓処理のおかげで ON/OFF でクリックは出ません |

### レイテンシーについて

Wet のアンカーは書き込みヘッドの後ろにあるため、その分だけ Wet は
遅れて聞こえます。本プラグインは **現在のアンカー量
（粒の長さ × ピッチのレート ＋ 2 ms）をホストにレイテンシーとして
報告** します（SIZE / PITCH を変えると追随します）。
YM ORPHEUS のような自動遅延補償（PDC）を持つホストでは、Dry と Wet の
タイミングが揃います。補償のないホストでは、Wet がわずかに遅れて
重なる「プリディレイっぽい」聞こえ方になります（クラウドの性格上、
実用上の問題は小さいです）。

### テイル

粒と FREEZE の性質上テイルは実質無限ですが、ホスト申告は有限の
**2.0 秒** にしてあります（FREEZE は申告テイルを超えて鳴り続けます）。

## パラメーター

| パラメーター | 範囲 | 初期値 | 内容 |
|---|---|---|---|
| Size | 10–200 ms | 80 ms | 粒の長さ。短いと粒々感、長いと滑らかな雲 |
| Density | 0–1（約 2–80 粒/秒） | 0.5 | 粒の発火頻度 |
| Pitch | −12–+12 st | 0 st | 粒の再生ピッチ。+12 でシマー、−12 で重い雲 |
| Spread | 0–1 | 0.5 | 粒のパンの広がり＋デチューン量。0 で全粒センター |
| Smear | 0–1 | 0.3 | 読み位置のランダムなばらつき（最大 +2 秒の履歴） |
| Freeze | on/off | off | バッファーを凍結し、雲を持続させる |
| Mix | 0–1 | 0.5 | Dry / Wet のクロスフェード |
| Output | −24–+12 dB | 0 dB | 出力ゲイン |
| Pitch CC | 0–127 | 1 | PITCH を操作する MIDI CC 番号（0 = 無効） |
| Freeze CC | 0–127 | 64 | FREEZE を操作する MIDI CC 番号（0 = 無効） |
| Bypass | on/off | off | エフェクトのバイパス（ホストのバイパスボタンとも連動） |
| Bypass CC | 0–127 | 65 | バイパスを操作する MIDI CC 番号（0 = 無効） |

## MIDI CC コントロール（v1.1）

v1.1 から、PITCH / FREEZE / バイパス（ON/OFF）を MIDI CC で操作できます。
チャンネルは問いません（オムニ受信）。CC が届くとパラメーター自体が
書き換わるので、画面のツマミやボタンも追随し、ホストのオートメーション
にもそのまま記録されます。

| 対象 | 初期 CC | 動き |
|---|---|---|
| PITCH | CC 1（モジュレーションホイール） | 値 0–127 を −12–+12 st に線形マッピング。中央の 62–65 はデッドゾーンで、ちょうど 0 st になります。変化は既存の約 50 ms の平滑化で滑らかに追随します |
| FREEZE | CC 64（サステインペダル） | 値 64 以上で ON、未満で OFF（ペダルを踏んでいる間だけ凍るモーメンタリー動作） |
| バイパス | CC 65 | 値 64 以上でエフェクト ON、未満でバイパス。切り替えは約 15 ms の等パワー・クロスフェードでクリックなし。バイパス中は原音がそのまま通り（MIX / OUTPUT は効きません）、書き込みヘッドは回り続けるので、戻したときに古い音が蘇ることはありません |

### MIDI ラーン（割り当ての変更）

画面下の MIDI CC ストリップで、各対象の割り当て CC を変更できます。

1. 対象（PITCH / FREEZE / BYPASS）の **LEARN** ボタンを押す（ボタンが点灯）
2. 使いたい MIDI コントローラーのツマミやペダルを動かす
3. 届いた CC 番号がその対象に割り当てられ、LEARN は自動で解除されます

- 割り当てはパラメーターとして保存されるので、プロジェクトを
  開き直しても残ります
- LEARN ボタンを**右クリック**すると割り当てが **Off**（無効）になります
- もう一度 LEARN を押すとキャンセル、別の LEARN を押すと対象が移ります
- CC 0 は「Off」の値として予約されているため、ラーンで割り当てることは
  できません
- 画面右下の **ON / BYPASS ボタン**でもバイパスを切り替えられます
  （ON のとき点灯）

### ホスト側の注意（正直な注記）

プラグイン自体は MIDI を受け取れるようになりましたが、**ホストが
エフェクトに MIDI をルーティングしてくれないと CC は届きません**。

- **Cakewalk Sonar**: エフェクトの MIDI 入力を有効にしてください
  （FX ラック／プラグイン設定で「MIDI 入力を有効化」するタイプの操作）
- **YM ORPHEUS**: エフェクトへの MIDI ルーティングはまだありません
  （別途対応予定）。現状は ORPHEUS 内では CC 操作は使えません

## ビルドとインストール

1. フォルダー内の **build.bat** をダブルクリック（初回は JUCE の
   ダウンロードで数分かかります）
2. `build → YMMirage_artefacts → Release → VST3` にできる
   **YM Mirage.vst3 フォルダーごと** を
   `C:\Program Files\Common Files\VST3` にコピー
3. ホスト側でプラグインの再スキャンを実行

詳しい手順は同梱の「かんたん手順.md」を見てください。

## 聴き方のチェックポイント

- ボーカルのステムに SIZE 80–150 ms / PITCH +12 / MIX 50%:
  声の上にオクターブ上の霧がかかる「シマー・クラウド」になるか
- FREEZE: 声やコードを鳴らしながら ON にすると、その瞬間の響きが
  無限パッドとして残り続けるか（入力を止めても鳴り続けるか）
- PITCH −12 / Size 150 ms / Smear 大: 低く重い雲になり、
  時間のばらつきでフレーズが滲むか
- Spread 0 ↔ 1 で雲の広がりがモノラル ↔ ワイドに変わるか
